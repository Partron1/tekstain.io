# UX Polish Prompt — Tekstain Nexus ESG Platform

Act as a senior UX/UI designer. Review and polish the existing Tekstain Nexus ESG and Carbon Management Platform interface to make it clear, professional, accessible, responsive, and easy to use for Ghanaian SMEs and users who may not be ESG specialists.

## Instructions

1. Inspect the existing application, design system, and project documentation before making changes. Preserve established product requirements and working functionality.
2. Improve visual hierarchy, spacing, typography, alignment, color consistency, navigation, forms, tables, dashboards, charts, buttons, and feedback states.
3. Make key workflows intuitive: onboarding, ESG data entry, evidence uploads, carbon results, data review, and ESG report generation.
4. Use plain language, helpful labels, contextual guidance, clear units, and understandable validation messages. Clearly distinguish zero, missing, estimated, and unverified data.
5. Ensure responsive behavior across desktop, tablet, and mobile. Follow accessible design practices, including readable contrast, keyboard navigation, visible focus states, and properly labeled form controls.
6. Maintain a consistent, trustworthy sustainability-focused visual style. Avoid unnecessary decoration, excessive gradients, misleading charts, and unsupported ESG scores.
7. Include polished loading, empty, success, error, and permission-denied states where relevant.
8. Reuse existing components and patterns where practical. Do not add unrelated features, change business logic, weaken security, or alter carbon calculations as part of visual polishing.
9. Make changes incrementally and verify affected screens and critical user journeys. Run available checks and tests; report what was actually tested and any issues that remain.

## Expected Outcome

Improve the existing UX without rebuilding the application unnecessarily. Summarize the key changes, files or components affected, checks performed, and any remaining usability issues. If a requirement is unclear or a change would affect core functionality, document the concern rather than guessing.
